# Contributing to TrayFold

Thanks for helping. TrayFold is deliberately small, so the most useful contributions are bug reports with logs and focused fixes.

## Build and test

Requires Xcode 26 on macOS 26.

```sh
Scripts/setup-signing.sh   # once per Mac: keeps the Accessibility permission across rebuilds
Scripts/run.sh             # Debug build + launch
xcodebuild -project TrayFold.xcodeproj -scheme TrayFold -destination 'platform=macOS' \
  -derivedDataPath build test
```

CI runs the same tests ad-hoc signed (`CODE_SIGN_IDENTITY=-`); a test that needs the Accessibility permission skips itself there.

`TrayFold.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and committed. You only need XcodeGen if you add or remove files or change `project.yml`: `brew install xcodegen && xcodegen generate`, and commit the regenerated project.

Logs: `/usr/bin/log show --predicate 'subsystem == "com.rezaahmadn.TrayFold"' --last 5m --info`.

## Rules the code keeps

- **No network.** No networking code, no updater, no telemetry.
- **Accessibility is the only permission by default.** Anything that needs another permission is an off-by-default option that asks only when turned on.
- **Swift 6 with strict concurrency, zero warnings.** UI code is `@MainActor`; blocking Accessibility calls run off the main actor with a timeout.
- **Small.** Under ~1,000 lines of Swift code in `TrayFold/` (comments and blank lines don't count), no third-party dependencies. Comments explaining *why* are welcome.
- **Testable logic is pure.** Decisions (what is hidden, how far to unfold, what a click does) live in `static` functions with unit tests; AppKit and Accessibility calls stay thin.
- **Logs name apps by bundle id**, never by menu item titles, which can be personal.

## Pull requests

One change per pull request, with a short description of what you tested on which Mac (model, macOS version, notch or not). CI must be green.
